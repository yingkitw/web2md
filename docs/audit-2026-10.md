# web2md Audit — 2026-10-26 (audit + ponytail lens)

> **Status: fixed same-day.** All Critical/High items and most Medium items were
> implemented in the same session (see git diff). Remaining open: M5, L1, L3.

Scope: Rust CLI/TUI (no web frontend — accessibility/responsive checks adapted to
terminal UX and code leanness). Build: clean, zero clippy warnings, 420 tests passing.

## Anti-patterns verdict

Not AI-slop. Real over-engineering smell is the opposite direction: **dead flags,
duplicated wiring, and tests parked in the wrong file.** No fixes applied — this is
a document, not a diff.

## Executive summary

- **3 critical, 2 high, 5 medium, 3 low** — none block functionality; all are deletions/simplifications.
- Biggest wins are pure deletion: ~60 lines of no-op flags, a 23-line redundant function, ~200 lines of duplicated option assembly.
- Overall quality: good. Healthy deps, gated features, strong test count.

## Critical

### C1. `--ignore-robots` is a documented no-op in 7 places
- **Location**: `src/cli.rs:179, 307, 377, 418, 485, 522`; `src/options.rs:144` (`_ignore_robots`)
- **Description**: Flag help text admits "No-op (robots.txt is off by default; kept for backward compatibility)". It parses, threads through `build_browser_options`, and is discarded.
- **Impact**: User-facing API surface that does nothing — the worst kind of dead code. "Kept for backward compatibility" for a pre-1.0 tool (v0.1.18) is cargo-culting.
- **Recommendation**: Delete the flags and the parameter. If a script breaks, the error message is self-explanatory.
- **Fix**: hand-edit or `/ponytail ultra`.

### C2. Tests for 5 modules live in `src/main.rs`
- **Location**: `src/main.rs:18-272` — tests for `ansi`, `tui`, `cli::url_to_filename`, `commands::domain_matches_any`, `commands::fetch::chunk_markdown_by_headings`, plus an html_to_md test that belongs in the lib.
- **Description**: Binary-crate test module imports from five unrelated modules.
- **Impact**: Violates the project's own convention (AGENTS.md: "Add inline `#[cfg(test)] mod tests` in the relevant source file"). Tests drift from the code they test.
- **Recommendation**: Move each test into its owning module file. Mechanical, zero-risk.

### C3. `format_label` duplicates `clap::ValueEnum`
- **Location**: `src/cli.rs:603-625`; used at `src/commands/fetch.rs:201, 541`
- **Description**: 20-arm hand-maintained match mapping `OutputFormat` → string. `OutputFormat` already derives `ValueEnum`; every label in the match is byte-identical to the variant's `to_possible_value()` name (clap derives kebab-case automatically, incl. `llms-txt`).
- **Impact**: Two sources of truth for the same mapping; add a 21st format and you must remember both.
- **Recommendation**: `format.to_possible_value().unwrap().get_name()` — delete the function.
- **Fix**: one-line edit.

## High

### H1. `build_browser_options` — 10 positional args, lint suppressed
- **Location**: `src/options.rs:135-162` (`#[allow(clippy::too_many_arguments)]`)
- **Description**: Function takes ten positional params; callers (fetch.rs:30-41, commands/mod.rs:38-49) pass field after field from args structs that share ~20 identical fields. Then fetch/browse each *re-mutate* the result with per-command flags (fetch.rs:42-60).
- **Impact**: The clippy lint is the correct opinion. Every new common flag touches 4 structs × 2 call sites.
- **Recommendation**: clap `#[command(flatten)]` a shared `CommonArgs` struct into `FetchArgs`/`BrowseArgs`/`BatchArgs`; replace the function with `CommonArgs::to_browser_options(&self)`. Deletes ~150 lines of field declarations and all call-site assembly.

### H2. Inline `BrowserOptions` assembly duplicated 6×
- **Location**: `src/commands/mod.rs` — Diff (71-77), Watch (120-125), Peek (212-227), Sitemap (277-282), Map (312-317), Search (355-360)
- **Description**: Each arm repeats `BrowserOptions::default()` + timeout/cookies/headers (and sometimes proxy/auth/delay) wiring. `BrowserOptions::default()` appears 8× in this file alone.
- **Impact**: Same bug fixed in N places instead of one (see ponytail: root-cause fix in the shared path).
- **Recommendation**: Small `fn base_options(timeout, cookie, header) -> BrowserOptions` helper, or fold into H1's `CommonArgs`.

## Medium

### M1. `run()` is a 435-line dispatch function
- **Location**: `src/commands/mod.rs:23-458`
- **Description**: Watch (~90 lines of polling loop), Peek (~60 lines of printing), Search, Map, Diff bodies are inlined in the dispatcher.
- **Impact**: Module docstring says "small command arms stay inline" — these aren't small. Watch's loop belongs in `watch.rs`.
- **Recommendation**: Move Watch and Peek bodies to their modules; `run()` becomes pure routing.

### M2. Inconsistent flag surface across commands
- **Location**: `FetchArgs` (60 flags) vs `Peek` (11) vs `Map` (9) vs `Sitemap` (4)
- **Description**: e.g. Peek takes `--no-blacklist` but not `--no-user-blacklist`/`--blacklist-file` that Fetch/Browse/Batch all have. Cookie file handling copy-pasted at fetch.rs:26-29, commands/mod.rs:34-37 (and silently missing elsewhere).
- **Impact**: Users can't predict which command accepts which flag; cookie-file support is silently absent from commands that take cookies.
- **Recommendation**: Same fix as H1 — flatten a shared args struct and the inconsistency disappears by construction.

### M3. Empty `docs/` directory
- **Location**: `docs/` (0 files)
- **Recommendation**: Delete it, or this audit goes there.

### M4. Pointless rebinding
- **Location**: `src/commands/fetch.rs:42` — `let mut options = options;`
- **Fix**: make line 30's binding `mut`. One word.

### M5. `resolve_url` (tui.rs:354) vs `PageToMarkdown::absolutize_links`
- **Description**: Two URL-resolution implementations (TUI's hand-rolled one vs the lib's). Behavior diverges on edge cases (e.g. fragments, malformed bases).
- **Recommendation**: TUI links come from the renderer already resolved where possible; otherwise delegate to the lib's logic. Low priority — current tests pass.

## Low

### L1. `OutputFormat` — 20 variants
- One `--format` enum value per Firecrawl output type. Deliberate parity per TODO.md, but it means `--format branding|links|images|...` are mutually exclusive one-shot modes that could be composable flags. Not a bug; revisit only if users ask to combine.

### L2. `AnsiRenderer` state fields `_in_header`, `col_alignments` etc.
- `ansi.rs` is fine, but `_in_header` is write-only (set, never read for decisions). Tiny dead state — delete.

### L3. No `cargo-udeps`/pub-API check
- `lib.rs` exports ~40 symbols; some (e.g. `extract_speakable`, `to_llms_txt_site`) are likely MCP-only. Not verified as dead — run `cargo udeps` + check each export has a caller before pruning. Ponytail rule: don't delete what you haven't confirmed unused.
